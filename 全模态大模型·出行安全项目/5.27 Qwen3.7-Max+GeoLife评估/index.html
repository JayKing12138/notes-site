    轨迹多任务理解：大模型能力上限评估报告¶

    评测模型： Qwen3.7-Max（DashScope API）
    数据集： GeoLife Trajectories 1.3（北京，2007–2012）
    提示策略： Few-shot（任务特定系统提示 + 结构化GPS输入）
    评测日期： 2026-05-27

    1. 实验设置¶

    1.1 任务与指标¶

    任务 全称 输入 Ground Truth 核心指标
    TTE 行驶时间估计 GPS 轨迹 实际时长（s） MAE, MAPE
    AD 轨迹异常检测 GPS 轨迹 Normal / Anomalous Accuracy, F1
    MP 移动预测 前 70% 轨迹 终点 Grid Cell（200m²） Acc@1km, Error (km)
    TMI 交通方式识别 GPS 轨迹 模式标签 F1, Exact Match
    Caption 轨迹描述生成 GPS 轨迹 规则生成描述 BLEU-1, ROUGE-L

    1.2 数据构造方式¶

    • TTE： 过滤条件 60s < 时长 < 7200s，距离 > 100m。N=17。
    • AD： Detour 异常（10% 的点偏移 d∈{1,3,5} 个 grid 单位）+ Switch 异常（在 μ∈{0.3,0.5} 处拼接另一条轨迹）。正常:异常 ≈ 5:1。N=17。对齐 GM-VSAE（Liu et al., 2020）构造方式。
    • MP： 输入前 70% 轨迹，GT = 最后一个 GPS 点所在 grid cell（200m×200m）。N=17。
    • TMI： GeoLife 人工标注子集，6 类交通方式。N=17。
    • Caption： 规则生成的轨迹描述（时间、地点、距离、速度、交通方式）。N=17。

    2. 评测结果¶

    2.1 总体性能¶

    任务 指标 数值 解读
    TTE MAE（均值） 52.8 s 优秀——中位数误差仅 15s
    MAPE 2.77% 相对误差极低
    AD Accuracy 76.5% 中等
    Precision 40.0% 误报率高
    Recall 66.7% 漏检 1/3 的异常
    F1 50.0% 弱——不可用于生产
    MP 平均误差 0.776 km 城市尺度下良好
    Acc@1km 88.2%（15/17） 优秀
    Acc@3km 94.1%（16/17） 接近完美
    TMI Mean F1 0.573 中等偏弱
    Mean Recall 57.4% 约 40% 的交通方式被漏判
    Exact Match 47.1% 不到一半完全正确
    Caption BLEU-1 0.061 词汇重叠率低
    ROUGE-L 0.077 语义覆盖率低
    Mode Recall 32.1% 交通方式严重缺失

    2.2 任务难度梯度¶

    简单 ◀────────────────────────────▶ 困难

TTE              MP              TMI             AD              Caption
(MAPE 2.8%)      (Acc@1km       (F1 0.57)       (F1 0.50)       (Mode Recall
                   88%)                                             32%)

    3. 分任务详细分析¶

    3.1 TTE — 行驶时间估计¶

    结论：✅ 大模型表现优秀，训练优先级低。

    统计量 数值
    MAE 最小值 0.0 s（精确匹配）
    MAE 中位数 15.0 s
    MAE 均值 52.8 s
    MAPE 均值 2.77%

    核心发现： 当元数据（距离、速度、时间戳）被显式提供时，模型可以近乎精确地计算行驶时间。误差主要出现在速度变化大的长距离多段轨迹中。

    最佳案例： tte_128_20100928013033 — GT=572s, Pred=572s（完全匹配）
    最差案例： tte_062_20071207102024 — GT=1417s, Pred=1175s（MAE=242s，约 17% 误差）

    启示： 在元数据充分的前提下，TTE 本质上是一个数值计算任务，大模型无需训练即可胜任。

    3.2 AD — 轨迹异常检测¶

    结论：⚠️ 中等水平，误报率高是主要问题。

    混淆矩阵 预测为 Normal 预测为 Anomalous
    实际 Normal TN=11 FP=3
    实际 Anomalous FN=1 TP=2

    失败模式分析：

    1. 误报（FP=3）： 模型将 GPS 采样间隔/噪声误判为异常
    2. 案例：正常轨迹中两点间有 69 分钟时间间隔 → 模型报告“瞬移” → 误报

    3. 根因：无法区分数据质量问题和行为异常

    4. 漏检（FN=1）： 高速公路轨迹上的 Detour 异常未被检测

    5. 案例：北京→天津行程中注入的绕路 → 模型认为“高速公路速度平滑” → 未发现偏移
    6. 根因：缺乏路网上下文，小尺度空间偏移在高速公路场景下不可见

    启示： 异常检测需要路网感知能力和数据质量预处理，纯 GPS + LLM 无法实现可靠检测。

    3.3 MP — 移动预测¶

    结论：✅ 表现优秀，Acc@1km = 88.2%。

    统计量 数值
    平均误差 0.776 km
    中位数误差 0.367 km
    Acc@1km 88.2%（15/17）
    Acc@3km 94.1%（16/17）

    最佳案例： mp_062_20081106104833 — 误差 27m（几乎精确）
    最差案例： mp_153_20120204121604 — 误差 6.15km（方向预测失败）

    核心发现： 当轨迹方向明确、终点在“前进方向上”时，LLM 预测效果好。失败发生在：

    • 轨迹表现为漫游/探索模式
    • 最后 30% 涉及明显方向变化

    启示： 对于方向明确的轨迹，MP 任务对 LLM 可行。训练可改善多停靠点复杂行程的预测。

    3.4 TMI — 交通方式识别¶

    结论：❌ 核心短板，必须训练。

    统计量 数值
    Mean F1 0.573
    Recall 57.4%
    Exact Match 47.1%

    按交通方式细分识别率（结合 100 条大样本评测数据）：

    交通方式 识别率 备注
    car ~100% 高速，容易识别
    taxi ~91% 与 car 特征相似
    bike 43% 常被误判为 car（尤其夜间）
    walk 49% 多模式轨迹中经常被遗漏
    bus 12.5% 几乎无法识别
    subway ~50% 样本不足

    关键失败模式： bus 几乎从未被正确识别——LLM 无法仅凭速度模式区分 bus 和 car/taxi。两者都表现为 20–50 km/h 且有停靠。

    案例： GT=[bus], Pred=[car, walk] — 模型看到中速 → 猜“car”，看到低速段 → 加“walk”。

    启示： 中速交通方式（bus、bike）的识别必须依赖领域训练或路网特征（公交线路、自行车道）。

    3.5 Caption — 轨迹描述生成¶

    结论：❌ 最弱任务，与 Ground Truth 差距显著。

    统计量 数值
    BLEU-1 0.061
    ROUGE-L 0.077
    Mode Recall 32.1%

    指标说明： BLEU/ROUGE 低有部分原因是 GT 格式差异（简洁模板 vs 冗长 LLM 输出）。交通方式召回率 32.1% 是关键信号——模型在生成自由文本时无法可靠识别交通方式。

    最佳案例： 短距离明确骑行轨迹 → 正确识别"cycling"并生成合理描述
    最差案例： 长距离夜间多模式轨迹 → 生成流畅但事实错误的描述

    启示： Caption 质量的瓶颈在于 TMI 准确率——如果模型无法识别交通方式，无论文本多流畅，caption 都会包含事实性错误。

    4. 大模型能力上限总结¶

    任务 LLM 上限 训练必要性 优先级
    TTE ~97%（MAPE 2.8%） 低——Prompt 即可胜任 ⬇️ 低
    MP ~88%（Acc@1km） 中——复杂行程需要训练 ⬆️ 中
    TMI ~57%（F1） 高——核心瓶颈 ⬆️⬆️ 高
    AD ~50%（F1） 高——需路网上下文 ⬆️⬆️ 高
    Caption ~32%（Mode Recall） 高——受制于 TMI ⬆️⬆️ 高

    5. 提示词优化建议¶

    基于评测结果，以下 Prompt 改进可在训练前部分缩小差距：

    5.1 TMI（影响最大）¶

    当前短板：bike/bus/walk 在中等速度段混淆。
建议增加的 Prompt 规则：
- 显式速度-模式映射："5-15 km/h → walk 或 bike；15-40 km/h → bike、bus 或拥堵中的 car"
- 时间模式："每 2-5 分钟规律停靠 → 大概率是 bus"
- 加速度模式："平滑加减速 → 机动车；不规则速度变化 → 步行/骑行"

    5.2 AD（影响较大）¶

    当前短板：GPS 噪声被误判为异常；真实绕路被遗漏。
建议增加的 Prompt 规则：
- "GPS 点之间的时间间隔不代表异常——它代表采样率变化"
- "关注空间偏移（相对直线路径的偏离），而非时间间隔"
- "连续 >90° 方向变化后回到原始航向 = 绕路嫌疑"

    5.3 Caption（依赖 TMI）¶

    策略：先修复 TMI，Caption 质量自动提升。
额外建议：要求结构化输出格式以提升指标对齐度：
"格式：地点:[城市]。日期:[YYYY-MM-DD]。时段:[时段]。时长:[X min]。距离:[X km]。交通……"

    6. 结论¶

    Qwen3.7-Max 在数值/空间计算类任务（TTE、MP）上表现优秀，这些任务的答案可直接从坐标和时间戳计算得出。但在语义推理类任务（TMI、AD、Caption）上存在根本性局限，这些任务需要：

    1. 领域知识（速度-模式映射、公交线路模式）
    2. 路网上下文（区分平行道路、识别公交站点）
    3. 多段推理能力（检测单条轨迹内的模式切换）

    以上结果证实了任务特定训练的必要性。大模型上限并非 100%——交通方式识别 F1 仅 57% 是核心瓶颈，其级联影响导致 AD 和 Caption 性能同步下降。

    建议训练优先级： TMI → AD → Caption → MP → TTE

    评测基于 GeoLife 数据集（17 样本/任务），使用 DashScope API 调用。

    模型：Qwen3.7-Max | 提示策略：任务特定系统提示 + 结构化 GPS 输入
