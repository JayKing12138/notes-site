    全模态大模型·出行安全项目进展

    一、项目目标与当前状态¶

    目标： 将 GPS 轨迹作为新模态接入大模型，支撑轨迹描述、异常识别、交通方式判断、行程时间估计和目的地预测五类任务，服务“司乘未分离检测”等安全风控场景。

    当前状态： 已完成从架构设计到 30B 模型训练落地的完整闭环，核心指标达到可用水平，架构和评测体系已沉淀为可复用资产。

    核心结论： 轨迹接入 LLM 的关键不是“端到端融合”，而是信息类型分工——数值走冻结 Head、空间模式走 latent token、语义生成走 LLM。单一通道方案已被实验证伪。

    二、架构演进与关键决策¶

    2.1 路线探索结论¶

    方案 结论 依据
    纯 Dense（BLUE→Connector→LLM） ❌ 不可行 分类任务可用（AD 84%），但数值任务命中率 0%——LLM 无法从 soft embedding 还原精确浮点
    纯文本（Symbolic Channel） ⚠️ 部分可行 数值精确（TTE MAPE=0%），但缺空间直觉，跨城 Fact Acc 仅 0.24
    纯视觉（地图渲染） ❌ 工程不可持续 渲染延迟高（调高德 API），数值丢失
    MCTA 三通道（Symbolic+Dense+Visual） ⚠️ 有效但冗余 三通道 token 竞争，Visual 通道引入额外延迟
    Contrastive Alignment（v3–v8） ❌ 全部失败 小数据+frozen encoder 下对比学习信号太弱，6 轮迭代均未收敛
    Dual–Channel Forward（v10–v11） ✅ 当前方案 信息类型分工，双通道互补，工程可持续

    2.2 当前架构：Dual-Channel Forward¶

    基于 Qwen3-Omni-30B-A3B（MoE thinker），hidden_size=2048：

    Dense Latent 通道：BLUE 编码器（冻结）→ TrajectoryConnector（128→512→2048, GELU+LayerNorm）→ 1 个 latent token，承载空间几何模式。

    Perception Token 通道：3 个独立预训练冻结 Head 各自输出判别结果 → Per-task Perception Projector（每个 ~1.8M 参数）→ 3 个 token，承载精确数值锚点。

    组件 参数量 状态 作用
    BLUE 编码器 ~85M 冻结 轨迹→128d latent
    AD Head（128→64→1） ~8K 冻结 异常概率，PR-AUC=1.0
    TMI Head（153→256→128→6） ~0.2M 冻结 交通方式，F1=0.85
    TTE Head（153→512→128→1） ~0.4M 冻结 行程时间，MAPE=3.39%
    TrajectoryConnector 5.4M 可训练 latent→LLM token 空间
    3× Perception Projector 5.4M 可训练 判别结果→LLM token 空间
    LoRA（rank=8，q/k/v/o×48层） 26MB 可训练 LLM 指令微调
    Qwen3–Omni–30B thinker 30B 冻结+LoRA 语义生成

    总可训练参数 ~37MB，4 卡 A100 即可训练 30B 模型。

    2.3 关键设计决策（均为消融验证）¶

    冻结 Head vs 可训练 Head： 冻结。3 个 Head 独立预训练已达 SOTA 水平，解冻后梯度通过 Projector 回传会破坏判别边界。

    Per-task 独立 Projector vs 混合 Projector： 独立。v5 用单个 Projector 混合 AD（1d）+TMI（6d），消融发现连续概率和离散 logits 语义不同，混压互相干扰。

    Latent token 数量： v8 用 1 个（信息瓶颈，被文本淹没）→ v10 用 4 个（空间分段保留更多几何信息，MP 提升明显）→ v11 回到 1 个（30B 注意力容量足够，perception token 已提供数值锚点）。

    统一 Report vs 独立任务： 统一。5 个独立 prompt 导致多任务 token 竞争，AD gen F1=0。合并为 2 个任务（Report 含 TMI/AD/TTE/Caption + MP）后 AD gen F1 从 0 到 0.767。

    三、工程问题与解决方案¶

    3.1 训练侧¶

    问题 根因 解决方案 结论
    DDP + 全冻结 LLM 死锁 冻结参数无梯度，DDP reducer 永久阻塞 改用 device_map="auto" 替代 DDP 30B 模型多卡训练首选 device_map
    跨卡 logits device mismatch device_map 将 lm_head 切到 cuda:1，与 labels 不同卡 手动 gather labels 到 logits 所在卡 30B+device_map 的必踩坑
    长文本 loss 主导短文本分类 标准 shift CE 按 position 取均值，Caption 200 token 淹没 AD 1 token 改用 sample-level CE（先 sample 内均值，再 batch 均值） 多任务训练的 loss 平衡必备
    AD token 沉默（gen F1=0） ①多任务 token 竞争
    ②150K 词表先验偏置    		 ①统一 Report
    ②2-way restricted CE（只在 2 个候选 token 间 softmax）+ anomaly token 加权    		 训练阶段做 restricted CE 比推理阶段 decoding 更有效
    显存 OOM（max_length=8192） 30B 模型激活值过大 gradient checkpointing + BF16 混合精度 + 梯度累积 显存降 60%，速度降 30%，可接受

    3.2 推理侧¶

    问题 根因 解决方案 结论
    TTE MAPE=99.6%，TMI Acc=5.4% Qwen3.5 thinking block 干扰输出解析，解析器提取到 thinking 中的错误数字 system prompt 加 /no_think 结构化输出任务必须关 thinking，TMI Acc 5.4%→84%
    推理速度慢 单卡逐条推理 vLLM tensor parallel（4卡）+ continuous batching 500 条评测从 163s 降到 84s，提速 ~2x

    3.3 数据侧¶

    问题 根因 解决方案 结论
    通用 Stage-1 Connector 降分 20k 步通用对齐无任务目标，引入噪声 改为任务特定对齐 SFT 通用对齐有害（ROUGE-L 0.493<0.516），必须有任务目标
    跨城 zero-shot 性能差 纯文本通道缺空间泛化 加入 Dense Channel 后空间信息可迁移 GeoLife Fact Acc 0.24→0.87

    四、当前指标（Porto 测试集）¶

    任务 指标 结果 冻结 Head 直出 说明
    MP ACC@1 / ACC@5 37.5% / 65.0% — 空间推理，需 latent+perception 协同
    TMI macro-F1 0.85 0.85 LLM 生成保持不退化 ✅
    AD PR-AUC / F1 0.873 / 0.767 1.0 / — 统一 Report 后 gen F1 从 0→0.767
    TTE MAPE 17.7% 3.39% LLM 生成精度低于 Head 直出，perception token 提供锚点
    Caption ROUGE-L 0.40 — 统一 Report 下的生成质量

    关键结论：

    • TMI 和 AD 的 LLM 生成指标与冻结 Head 持平或接近——说明 perception token 成功将 Head 的判别能力传递给了 LLM，且没有退化
    • TTE 的 LLM 生成 MAPE（17.7%）高于 Head 直出（3.39%）——LLM 从数值锚点生成精确数字仍有信息损耗，这是自回归生成的固有局限
    • MP 是纯 LLM 推理任务（无对应 Head），37.5% 的 ACC@1 说明 latent token 提供了有效的空间信息

    五、沉淀与可复用物¶

    5.1 架构资产¶

    1. Dual–Channel Forward 框架： LLM-agnostic 的“轨迹→LLM”适配协议，已验证接入 Qwen3.5-9B 和 Qwen3-Omni-30B。BLUE 编码器可替换为任意轨迹编码器，Head 可按需增减。
    2. 冻结 Head + Perception Projector 范式： 适用于任何“已有成熟判别模型 + 需接入 LLM 做生成”的场景。Head 冻结保证判别不退化，Projector 仅 ~1.8M 参数即可完成映射。
    3. 统一 Report 范式： 多任务合并为单一生成目标，消除 token 竞争。适用于任何多任务 LLM 训练场景。

    5.2 工程模板¶

    • 30B MoE 训练模板：device_map 多卡切片 + gradient checkpointing + LoRA + sample-level CE
    • vLLM 批量推理模板：tensor parallel + continuous batching
    • BLUE latent 预计算管线：一次性预计算，训练/推理直接加载

    5.3 方法论沉淀¶

    1. 信息类型分工原则： 数值→冻结 Head，模式→latent token，语义→LLM。适用于任何多模态接入场景。
    2. 消融驱动决策： 每个架构决策（token 数量、Projector 独立性、Head 冻结、任务合并）都有对照实验。
    3. 双目标门禁标准： 新增能力提升 + 原有模块不退化，保障能力扩展不损害基座。

    5.4 已验证的避坑结论¶

    坑 结论 适用范围
    LLM 无法从 embedding 读精确浮点 数值信息必须走文本或 Head 直出 所有 soft embedding→LLM 方案
    Contrastive Alignment 小数据不可用 小数据+frozen encoder 转向 generative alignment 对齐层训练路线选择
    通用 Connector 无任务目标有害 必须做任务特定对齐 SFT Stage-1 训练设计
    Qwen3.5 thinking 干扰结构化输出 结构化任务必须 /no_think 所有 Qwen3.5 下游任务
    DDP+全冻结 LLM 死锁 用 device_map 或 find_unused_parameters 冻结大模型训练
    分类高准确率可能是 label 先验假象 必须用数值任务交叉验证 任何分类任务评测

    六、下一步计划¶

    1. TTE 生成精度优化： 当前 LLM 生成 MAPE=17.7% vs Head 直出 3.39%，差距较大。计划探索 multi-token perception（让 TTE Head 输出多位数字 token 而非单个锚点）。
    2. omni_enhanced 图像接入： 已渲染 1123/1333 条订单的增强地图图像（主地图+起终点嵌入图+危险 POI 可视化），待接入 Qwen3-Omni-30B 原生视觉通道做第三通道验证。
    3. 司乘未分离专项评测： 构造模拟未分离场景数据，基于现有 AD+MP 能力做端到端业务指标评测。
    4. GeoLife 跨城验证： 在 Porto 训练的模型上做 GeoLife zero-shot 评测，验证空间信息迁移能力。
