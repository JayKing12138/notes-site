    训推不一致（Exposure Bias / Distribution Shift）¶

    🚗

    SFT 的问题在于，训练时永远跟着真实标签走，模型从未见过次优状态下该怎么办。推理一旦选了次优前缀，后续就会雪球式放大错误，一发不可收拾。

    RL 改进了这一点——让模型见到自己生成的轨迹，但奖励信号太稀疏，只在序列末尾给一个总分，无法追溯到底是哪个 token 走错了。

    OPD 结合了两者的优点：以学生模型自己生成的轨迹为训练上下文（解决 SFT 看不到次优状态的问题），同时在每个 token 上施加教师模型的监督信号（解决 RL 奖励稀疏、无法 token 级纠偏的问题）。

    训练时模型看到的上下文 ≠ 推理时自己生成的上下文。三种方法对这一矛盾的处理方式本质不同。

    SFT（监督微调）¶

    • 机制：Teacher Forcing，训练时输入恒为真实历史 token，优化下一步条件似然。
    • 症结：训练时输入是真实历史 token，推理时输入是模型自己生成的 token，两者分布不一致。模型未见过自身生成的次优前缀，导致隐状态外推失效，暴露偏差被直接固化。

    RL（强化学习，如 PPO）¶

    • 机制：以完整生成序列为轨迹，依据奖励模型反馈进行策略梯度优化，最大化期望累积奖励。
    • 症结：奖励信号为稀疏的序列级标量，无法对中间解码步提供逐点约束。模型无法辨识早期 token 偏移对后续轨迹的因果影响，仅能事后规避低分轨迹，无法抑制中间状态的分布漂移。

    OPD（在线策略蒸馏）¶

    • 机制：训练时引入教师模型（历史 checkpoint 或并行大模型），针对学生当前自生成的中间上下文，输出软概率分布作为逐 token 监督信号，通过 KL 散度将纠偏能力蒸馏至学生。
    • 优势：监督粒度细至解码步，且监督上下文覆盖含噪轨迹。学生同时拟合真实分布与教师在偏离轨迹上的条件分布，本质上是在训练条件纠偏映射——给定模型自己采样出的含噪前缀，预测下一步应该输出什么分布，使推理时的误差累积被显式建模并压制。
